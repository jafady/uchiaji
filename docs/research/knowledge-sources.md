# 下処理・コツの知識源と読み取り

調査日：2026-11-02

下処理・コツ・理由を「初めて調べたときに自分の言葉で残し、次から手順の中で開く」ために、ユーザーが実際に見ている情報源の形式と、読み取りを支援する手段を調べた。きっかけはユーザーの発言「だいたいテレビ番組か食品メーカーのwebページから読んでやってみる感じだから、その読み取りがあればさらに嬉しい」（[concept.md](../concept.md) の「体験の核」）。

レシピとしての取り込みやすさは [import-sources.md](import-sources.md)、メディアのプロフィールは [recipe-media.md](recipe-media.md) にある。ここでは、その差分だけを書く。

## 結論

- 【事実】番組とメーカーのページは、形式がばらばらである。レシピは JSON-LD で取れるものがあるが、コツや下処理は、PDF、JavaScript で描画するページ、構造化データのない HTML に分かれる。
- 【推測】ページを自動で解析する作り込みは壊れやすい。「その場のスクショや写真から AI が自分の言葉の下書きを作り、本人が直して出典を付ける」形が現実的である。費用は 1 枚 0.1 円未満の見込み。
- 【推測】番組の公式テキストは残りにくい。「見たその日に、自分の言葉で残す」価値が大きい。

## 読み取りの手段

| 手段 | 状況 | 費用 | 備考 |
|---|---|---|---|
| 端末の文字認識（iPhone のテキスト認識表示） | 【事実】iOS 16 から日本語に対応し、動画にも広がった | 0 円 | 画像の文字を選んで、アプリに貼れる。Android の Google レンズは未確認 |
| AI での下書き（スクショ・写真から） | 【推測】画像 1 枚で入力約 2,000、出力約 400 トークンなら、Claude Haiku 5.5 で約 0.0004 ドル | 月数十枚でも数円 | 【推測】出力は「下処理／コツ／理由」の 3 層の欄に入れ、本人が直し、出典（番組名と放送日、URL）を付ける。料金は [ai-services.md](ai-services.md) |
| 放送の字幕・録画の取り込み | 【事実】著作権法 30 条 1 項は私的使用の複製を認めるが、2 号で、技術的保護手段の回避により可能になった複製を知りながら行う場合を除く | ― | 【推測】アプリの機能にしない。一般論であり、法的な助言ではない（[legal.md](legal.md)） |

## uchiaji にとっての意味

- **活かす**
  - 【推測】下処理の参照先には、出典付きで固定 URL の HTML を選ぶ（キッコーマン「料理の基本」、県の水産課のページなど）。
  - 【推測】テレビの画面写真やスクショから 3 層の下書きを作り、本人が直す。民放やガッテンのように公式テキストのない情報源に強い。
  - 【推測】その場合も、元の画像は保存しない。残すのは本人が直した要点と出典だけにする（[principles.md](../principles.md) P-2、backlog の N-04）。
  - 【推測】外部の AI に画像を送ることは、P-3 の「外部の LLM に本文を送る場合は、サイトの規約を確認する」に当たる。番組や配信サービスの規約での扱いは未確認。
- **避ける**
  - 番組ページの HTML を自動で解析する作り込み。【推測】JavaScript での描画やページの消滅で壊れやすい。
  - 放送の字幕や録画を取り込む機能。
- **独自の機会**
  - 【推測】番組で見たコツを、出典付きの自分の言葉で残す流れは、既存のレシピ管理アプリ（レシピの取り込みが中心）にない。
