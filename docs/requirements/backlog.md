# 要件候補

要件定義の出発点となる候補のリスト。まだ確定していない。

- **優先度**：Must / Should / Could は調査から付けた仮の値。MVP の範囲を決めるときに見直す。
- **根拠**：[lessons.md](lessons.md) の ID と、[principles.md](../principles.md) の原則番号（P-番号）で示す。
- **場面**：決める / 作る / 振り返る / 共通

## 非機能要件

| ID | 要件候補 | 優先度 | 根拠 |
|---|---|---|---|
| N-01 | 全件を書き出せる（JSON-LD / Markdown / Cooklang 互換を検討） | Must | L-5-01, L-5-03, P-4 |
| N-02 | 課金状態にかかわらず、データを消さない。閲覧と書き出しは常にできる | Must | L-5-02, L-5-06, P-4 |
| N-03 | 他人のレシピで課金しない。取り込み件数で制限しない | Must | L-1-06, L-5-07, P-1 |
| N-04 | 元の写真・本文を丸ごと保存しない | Must | L-5-05, P-2 |
| N-05 | 取り込みは本人の操作で 1 件ずつ行う。robots.txt と AI 利用拒否の指定に従う | Must | P-3 |
| N-06 | 日本の分量表記（大さじ・小さじ・カップ・合・適量・少々・ひとつまみ・1 片）と時間表記（5分、1時間半、10〜15分）を扱える | Must | L-1-05, L-UX-12 |
| N-07 | スマホの縦画面を前提にする | Must | concept.md |
| N-08 | 調理モードはオフラインでも使える | Should | L-UX-09 |

## 次に決めること

- MVP の範囲：Must の中から、さらに最初の 1 本に絞る。
- 形態と技術スタック：N-07 と N-08、F-CK-01（Wake Lock）から、PWA が有力な候補になる。
- データの置き場所と同期の方法：N-01 と N-02 を満たす方式にする。
- 知識（F-KN-*）の作り方：自前で書く / AI で生成する / 出典付きで参照する。
